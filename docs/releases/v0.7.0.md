# Skill Manager 0.7.0 Public Preview

This feature preview turns a blocked repository update into a named diagnosis
and adds one confirmed repair for the only repairable cause. It supersedes
`v0.6.0` for Apple Silicon Macs running macOS 13 or newer.

## Downloads

- `skill-manager-desktop-0.7.0-macos-arm64.zip` — `Skill Manager.app` with the
  Dashboard, Skills, Skill Sets, and Sources interfaces.
- `skill-manager-cli-0.7.0-macos-arm64.tar.gz` — the `skill-manager` CLI/TUI,
  advisor activation API, README, MIT license, and third-party notices.
- `SHA256SUMS.txt` — SHA-256 digests for both archives.

Download `SHA256SUMS.txt` with the artifacts and verify both archives from the
same directory:

```bash
shasum -a 256 -c SHA256SUMS.txt
```

## What Changed

- Added **`skill-manager repair <git-url> [--dry-run]`**. When a skill writes
  generated files into its own managed checkout, update stops; repair lists the
  offending checkout-relative paths, moves them into `~/.skill-manager/trash`,
  restores tracked files from the last fetched commit, and then deletes the
  staged copy. An explicit Git URL is always required.
- **`update` now explains why it stopped.** Every checkout blocker is classified
  and reported with a readable cause. Repairable failures print the exact
  `repair` command; detached HEAD, local commits, a changed origin, and link
  drift are explained and left for you to decide.
- **The Sources screen reports `Needs repair`** before any update is attempted,
  with a per-source Repair action. A failed update offers the same repair from
  its dialog, and the confirmation lists every path that will be removed.
- Repair only clears worktree changes. It never runs `git clean` or
  `reset --hard`, never leaves the managed checkout root, never writes
  `state.json` or moves symlinks, and refuses to move an installed skill
  directory or a `SKILL.md` that the last fetched commit cannot restore.
- A failed repair restores the exact pre-operation state: staged paths are moved
  back, the Git index is restored, and files the repair recreated are removed.
  If any part of that cannot be completed, the recovery data is kept and the
  error names what failed.

## Desktop Installation

1. Expand `skill-manager-desktop-0.7.0-macos-arm64.zip`.
2. Move `Skill Manager.app` to `/Applications`.
3. Control-click the application, choose **Open**, and confirm **Open**.

The application is ad-hoc signed but not Developer ID signed or notarized. If
macOS does not offer **Open**, try a normal launch once, then use **System
Settings → Privacy & Security → Open Anyway** after verifying the checksum and
that this release came from the expected repository.

## CLI Installation

```bash
tar -xzf skill-manager-cli-0.7.0-macos-arm64.tar.gz
install -m 0755 \
  skill-manager-cli-0.7.0-macos-arm64/skill-manager \
  "$HOME/.local/bin/skill-manager"
skill-manager --version
```

The expected version output is `skill-manager 0.7.0`.

The Skill Advisor remains opt-in. After installing the CLI, install the
first-party skill from this repository:

```bash
skill-manager install https://github.com/dees91/agent-skill-manager \
  --tool both --skill skill-advisor
```

Preview a repair before it moves anything:

```bash
skill-manager repair https://github.com/example/agent-skills --dry-run
```

## Preview Limitations

- This is a public preview, not a stable release.
- Only Apple Silicon macOS 13 or newer is supported by these binaries.
- There is no Developer ID signature, notarization, universal binary, DMG,
  auto-update, telemetry, SBOM, or build provenance attestation.
- Skill Manager uses fixed provider paths under the current user's home
  directory. Custom Claude, Codex, Muse, or Grok skill roots, `GROK_HOME`,
  project-level skill directories, and provider plugin skills are out of scope.
- Repair clears worktree changes only. A checkout with local commits, a detached
  HEAD, a changed origin, or managed link drift is diagnosed but not resolved,
  and a checkout whose installed `SKILL.md` was deleted locally stays blocked by
  the ownership audit that also guards update and uninstall.
- Files cleared by repair are removed once the checkout verifies clean. The
  trash staging exists so a failed repair can roll back, not as a recycle bin.
- Muse and Grok have no provider diagnostic, so their context-budget figures
  are always filesystem estimates against an assumed context window.
- Experimental skills.sh Discover code is not exposed in this build.
- Already running Claude Code, Codex, Muse, or Grok sessions may need to be
  restarted after skill visibility changes.
- Third-party skills contain instructions that Skill Manager does not audit or
  sandbox. Review their source before installing them.
