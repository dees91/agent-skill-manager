# Skill Manager 0.8.0 Public Preview

This feature preview reports skills that a managed Git repository gained after
you installed it and makes them one step to install. It supersedes `v0.7.0` for
Apple Silicon Macs running macOS 13 or newer.

## Downloads

- `skill-manager-desktop-0.8.0-macos-arm64.zip` — `Skill Manager.app` with the
  Dashboard, Skills, Skill Sets, and Sources interfaces.
- `skill-manager-cli-0.8.0-macos-arm64.tar.gz` — the `skill-manager` CLI/TUI,
  advisor activation API, README, MIT license, and third-party notices.
- `SHA256SUMS.txt` — SHA-256 digests for both archives.

Download `SHA256SUMS.txt` with the artifacts and verify both archives from the
same directory:

```bash
shasum -a 256 -c SHA256SUMS.txt
```

## What Changed

- **`update` reports new skills.** When a repository you installed later adds
  skills, `update` still installs nothing, but it now lists the skills that are
  not installed and prints the exact command that adds them for the tools the
  repository already uses:

  ```text
  new skills in example/agent-skills (not installed): new-skill, other-skill
    install: skill-manager install https://github.com/example/agent-skills --skill new-skill --skill other-skill
  ```

  `update --dry-run` lists new skills already in the local checkout; it still
  does not fetch.
- **The Sources screen shows new skills** on a healthy Git source, with an
  **Install new** action. It opens the install matrix on the existing checkout
  with only those skills preselected for the tools the source already uses.
  Already installed skills keep their current ON or OFF state.
- Skill names come from upstream directory names, so every argument in the
  suggested command is shell-quoted. A name containing control characters is
  shown quoted and the command is left out.
- If new skills cannot be checked, for example because two skills share a name,
  the update still succeeds and both interfaces show the reason.
- The README is now a short desktop-first introduction, and the complete CLI,
  TUI, source, and troubleshooting guide lives in `docs/usage.md`.

## Desktop Installation

1. Expand `skill-manager-desktop-0.8.0-macos-arm64.zip`.
2. Move `Skill Manager.app` to `/Applications`.
3. Control-click the application, choose **Open**, and confirm **Open**.

The application is ad-hoc signed but not Developer ID signed or notarized. If
macOS does not offer **Open**, try a normal launch once, then use **System
Settings → Privacy & Security → Open Anyway** after verifying the checksum and
that this release came from the expected repository.

## CLI Installation

```bash
tar -xzf skill-manager-cli-0.8.0-macos-arm64.tar.gz
install -m 0755 \
  skill-manager-cli-0.8.0-macos-arm64/skill-manager \
  "$HOME/.local/bin/skill-manager"
skill-manager --version
```

The expected version output is `skill-manager 0.8.0`.

The Skill Advisor remains opt-in. After installing the CLI, install the
first-party skill from this repository:

```bash
skill-manager install https://github.com/dees91/agent-skill-manager \
  --tool both --skill skill-advisor
```

Check a repository for skills added since you installed it without fetching:

```bash
skill-manager update https://github.com/example/agent-skills --dry-run
```

## Preview Limitations

- This is a public preview, not a stable release.
- Only Apple Silicon macOS 13 or newer is supported by these binaries.
- There is no Developer ID signature, notarization, universal binary, DMG,
  auto-update, telemetry, SBOM, or build provenance attestation.
- Skill Manager uses fixed provider paths under the current user's home
  directory. Custom Claude, Codex, Muse, or Grok skill roots, `GROK_HOME`,
  project-level skill directories, and provider plugin skills are out of scope.
- New skills are never installed automatically, and there is no way to dismiss
  one you do not want. A skill stops being reported only after it is installed.
- New skills are matched by name. A recorded skill that moved to another path
  in the repository is not reported as new.
- Repair clears worktree changes only. A checkout with local commits, a detached
  HEAD, a changed origin, or managed link drift is diagnosed but not resolved.
- Muse and Grok have no provider diagnostic, so their context-budget figures
  are always filesystem estimates against an assumed context window.
- Experimental skills.sh Discover code is not exposed in this build.
- Already running Claude Code, Codex, Muse, or Grok sessions may need to be
  restarted after skill visibility changes.
- Third-party skills contain instructions that Skill Manager does not audit or
  sandbox. Review their source before installing them.
